## 编程作业

`sys_enable_deadlock_detect` 实现非常简单，就是多维护一个字段，没什么好说的。

银行家算法，虽然学 OS 的时候看着很简单，用手去模拟也很简单，但是这次真放在内核中自己实现的话，要考虑的事情真的太多了，实现起来也不简单。我们从头到尾一步步来，下面就仅仅以 `mutex` 为例来说明，信号量与它的区别仅仅在于初始值不同，就不重复说明了：

- 在 PCB 里新增字段：`detect_deadlock`、`available`、`alloc`、`need`
- 新建线程时，需要给 `alloc`、`need` 新建一行，由于开始对 `mutex` 没有需要也没有分配，所以全置为 0 即可，这里根据分配 `pid` 方式的不同，也要对应选择是直接覆盖还是新插入。有三处位置调用了 `TCB::new`，分别是 `PCB` 的 `new`、`fork`，以及 `sys_thread_create` 系统调用，但是我们不在这进行处理。最好的办法还是在 `TCB::new` 中进行处理，因为两个动作是绑定的。具体来说，我们先从 `alloc` 大小看父进程有多少子进程，如果大小 $\le$ `tid`，那么就该在后面插入一行 0；否则就遍历置 0。0 的个数相当于信号量个数，即 `available` 第一维的长度。
- 同理，新建一个锁时，`available` 要在后面插入一个 1，`alloc` 和 `need` 要插入一列 0。
- 在 `sys_mutex_lock` 中，就是银行家算法的主体部分：
  - 先让 `need[tid][mutex_id]` + 1，再开始进行题目中描述的模拟
  - 每次试着找一个元素，使得 `need[i][j] < work[j]`，回收所有的 `alloc[i][j]` 到 work 中
  - 直到找不到这样的元素，如果此时所有的 `finish` 不都为 `true`，那么直接 `need -= 1` 然后返回，你也不用等了，我不会给你分配；如果找到了，再继续执行 `lock`

- 接下来就是语义化处理。`sys_lock` 中，如果没拿到锁，就什么也不干；如果拿到锁了，就 `available -=1`，`alloc += 1`，`need -= 1`。在 `sys_unlock` 中，如果没找到继承人，就 `alloc -= 1`，`available += 1`；如果找到了继承人，就 `alloc[me] -= 1`，`alloc[new] += 1`，`need[new] -= 1`。
- 对结构有一点小小的改变，就是每个 `mutex` 记录自己的 id，不然后面完全没办法更新二维数组。不能加在 `lock` 或者 `unlock` 里传参，虽然这样不会改变结构，但是条件变量也要用锁，它是完全没办法知道 id 信息的，所以还是要改结构更方便。
